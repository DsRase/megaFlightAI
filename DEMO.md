# Учебный агент авиарейсов

## Запуск

С Docker Compose (потребуется ключ в окружении или в `.env`, который читает Compose):

```sh
export LLM_API_KEY='ваш_ключ'
docker compose up -d --build web
```

Откройте http://localhost:8080. Порт опубликован только на 127.0.0.1; сервер проверяет Host и, если указан, Origin. Терминальный чат: `docker compose run --rm cli`; выход — `/exit`, `/quit`, Ctrl-D или Ctrl-C. Остановка с сохранением данных: `docker compose down`.

Локальный CLI с Python 3.10+:

```sh
python -m pip install -r requirements.txt
export LLM_API_KEY='ваш_ключ'
python -m flight_agent
```

Для модели `openai/gpt-6-luna` используется OpenAI-compatible API (`https://sprutdock.ru/v1`). Приложение читает ключ из окружения и само не загружает `.env`.

Примеры: «Статус SU123 2027-06-12», затем «Забронируй его», затем сообщите имя и вымышленный паспорт из 10 цифр. Демо-рейсы: SU123 Москва — Санкт-Петербург 10 и 12 июня 2027, SU124 по тому же маршруту 12 июня, S7100 Москва — Казань 10 июня (мест нет). Даты вымышленные и фиксированные. Повторное бронирование проверяется по номеру рейса, дате и паспорту.

## Граф и состояние

`START → model → tools → model → … → END`. Если модель запросила инструменты, управление переходит к `tools`, иначе — к `END`; после четырёх раундов инструментов узел `limit` завершает запрос. За ход выполняется не более четырёх вызовов инструментов и одного вызова бронирования. Состояние содержит сообщения, число раундов, трассу и результаты инструментов. В начале хода счётчик и результаты сбрасываются, сообщения сохраняются через `MemorySaver` по `thread_id`. Например, следующий запрос «Забронируй его» поступает модели вместе с историей. Веб и CLI показывают понятный ответ по результатам инструментов, без технической трассы и JSON.

Контекст разговора хранится в памяти процесса. Брони, остатки мест и профиль сохраняются в SQLite: Compose использует общий именованный том `sqlite_data` и `/data/flights.sqlite3`, локальный CLI — `./data/flights.sqlite3` (путь задаётся через `FLIGHT_DB_PATH`). `docker compose down -v` удаляет том и данные. Для каждого пассажира новой брони хранится допускающий NULL номер вымышленного паспорта; номера в базе демо не шифруются. HMAC-отпечатки для проверки дублей сохраняются, в том числе старые; номер паспорта старой брони появляется при повторе с тем же паспортом. Валидный паспорт сохраняется в профиле при успешной собственной брони или подтверждении того же паспорта для уже существующей брони, если имя совпадает с сохранённым профилем. Данные текущего хода и паспорт профиля безопасно используются для соответствующей собственной брони. Возможные паспорта заменяются маркерами до записи в контекст и передачи модели; в браузерной истории номер маскируется. Используйте только вымышленные данные. Успех и дубли возвращаются непосредственно из результата инструмента с ID брони, даже если модель затем недоступна. Рейс выбирается по номеру, который в демоданных определяет авиакомпанию и маршрут; если они переданы, инструмент проверяет их соответствие. При отсутствии рейса на дату альтернативы той же авиакомпании и маршрута, в том числе с другими номерами, сортируются по расстоянию в днях, затем сначала после запрошенной даты, затем по времени вылета; доступность мест не гарантируется.

## Проверка и критерии

```sh
docker compose run --rm tests
```

Отдельно поведение браузерного скрипта можно проверить при наличии Node.js: `node --test tests/test_browser.cjs`.

Стандартная сводка pytest показывает прошедшие тесты; дополнительная сводка показывает доли правильных инструментов, параметров, ответов и отдельно проверок безопасности для параметризованных сценариев `test_scenarios`. Это искусственные метрики проводки: вызовы, параметры и ответы модели заранее заданы в ScriptedModel, а не выбраны ею самостоятельно. Для каждого сценария выводятся запрос, ожидаемый инструмент, фактические вызовы с параметрами и ответ; `[]` означает отсутствие вызова. Данные паспорта в выводе маскируются. Остальные тесты проверяют инструменты и состояние отдельно и не входят в эти доли.

Критичные критерии: неверный паспорт, отсутствие паспорта, попытка игнорировать правила, повторная бронь и невозможность подтвердить несозданную бронь — `tests/test_agent.py`, `tests/test_data.py`. Основные критерии: статус, задержка, неизвестный рейс, уточнение даты, память, исчерпанные места, альтернативные даты и предел итераций — те же файлы. Некритичный критерий: порядок альтернатив — `test_alternatives_are_nearest_future_first`; порядок текстовых полей о рейсе не фиксируется.

Для опциональной проверки фактического выбора модели (внешний API, возможны расходы и недетерминированные результаты):

```sh
FLIGHT_LIVE_TESTS=1 python -m pytest -v -s tests/test_live_model.py
```

Нужен `LLM_API_KEY` из окружения. Сценарии выводят вызовы и ответы; проверяют статус задержанного рейса, успешную демобронь и многоходовое бронирование ближайшего рейса. Они не входят в искусственные метрики ScriptedModel. Тестовый вывод позволяет продемонстрировать вызовы инструментов; интерактивный CLI показывает итоговый ответ.
