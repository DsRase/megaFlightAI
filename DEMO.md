# Учебный агент авиарейсов

## Запуск

Python 3.10+:

```sh
python -m pip install -r requirements.txt
export LLM_API_KEY='ваш_ключ'
python -m flight_agent
```

Для модели `deepseek/deepseek-v4-flash` используется OpenAI-compatible API (`https://sprutdock.ru/v1`). Compose-сервис `app` передаёт `LLM_API_KEY` в контейнер: `docker compose run --rm app`. Завершение CLI: `/exit` или Ctrl-D. Ключ читается только из окружения; приложение не загружает `.env`.

Примеры: «Статус SU123 2027-06-12», затем «Забронируй его», затем сообщите имя и вымышленный паспорт из 10 цифр. Демо-рейсы: SU123 Москва — Санкт-Петербург 10 и 12 июня 2027, SU124 по тому же маршруту 12 июня, S7100 Москва — Казань 10 июня (мест нет). Даты вымышленные и фиксированные. Повторное бронирование проверяется по номеру рейса, дате и паспорту.

## Граф и состояние

`START → model → tools → model → … → END`. Если модель запросила инструменты, управление переходит к `tools`, иначе — к `END`; после четырёх раундов инструментов узел `limit` завершает запрос. За ход выполняется не более четырёх вызовов инструментов и одного вызова бронирования; отклонённые запросы также видны в трассе. Состояние содержит сообщения, число раундов, трассу и результаты инструментов. В начале хода счётчик и результаты сбрасываются, сообщения сохраняются через `MemorySaver` по `thread_id`. Например, сообщение о SU123 попадает в историю, вызов статуса добавляет ответ инструмента, а следующий запрос «Забронируй его» поступает модели вместе с историей. Каждая строка CLI показывает вызванные инструменты, их аргументы и результаты с маской паспорта, затем JSON-ответ с `status`, `message`, `missing_fields`, `alternatives`.

Брони и память хранятся только в процессе. Возможные паспорта в сообщении заменяются временными маркерами до сохранения и передачи модели; оригинал доступен инструменту только в текущем ходе. В брони хранится ключевой HMAC паспорта для проверки дубля, ключ существует только в процессе. Для демонстрации используйте вымышленные данные. Успех и дубли возвращаются непосредственно из результата инструмента с ID брони, даже если модель затем недоступна. Рейс выбирается по номеру, который в демоданных определяет авиакомпанию и маршрут; если они переданы, инструмент проверяет их соответствие. При отсутствии рейса на дату альтернативы той же авиакомпании и маршрута, в том числе с другими номерами, сортируются по расстоянию в днях, затем сначала после запрошенной даты, затем по времени вылета; доступность мест не гарантируется.

## Проверка и критерии

```sh
python -m pytest -v -s
```

Стандартная сводка pytest показывает прошедшие тесты; дополнительная сводка показывает доли правильных инструментов, параметров, ответов и отдельно проверок безопасности для параметризованных сценариев `test_scenarios`. Это искусственные метрики проводки: вызовы, параметры и ответы модели заранее заданы в ScriptedModel, а не выбраны ею самостоятельно. Для каждого сценария выводятся запрос, ожидаемый инструмент, фактические вызовы с параметрами и ответ; `[]` означает отсутствие вызова. Данные паспорта в выводе маскируются. Остальные тесты проверяют инструменты и состояние отдельно и не входят в эти доли.

Критичные критерии: неверный паспорт, отсутствие паспорта, попытка игнорировать правила, повторная бронь и невозможность подтвердить несозданную бронь — `tests/test_agent.py`, `tests/test_data.py`. Основные критерии: статус, задержка, неизвестный рейс, уточнение даты, память, исчерпанные места, альтернативные даты и предел итераций — те же файлы. Некритичный критерий: порядок альтернатив — `test_alternatives_are_nearest_future_first`; порядок текстовых полей о рейсе не фиксируется.

Для опциональной проверки фактического выбора модели (внешний API, возможны расходы и недетерминированные результаты):

```sh
FLIGHT_LIVE_TESTS=1 python -m pytest -v -s tests/test_live_model.py
```

Нужен `LLM_API_KEY` из окружения. Сценарии выводят ожидаемый и фактический инструмент, параметры и ответ; проверяют статус задержанного рейса и успешную демобронь. Они не входят в искусственные метрики ScriptedModel. Реальный интерактивный выбор также виден в CLI.
