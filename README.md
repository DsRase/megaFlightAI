# megaFlightAI

Учебный агент на LangGraph помогает в чате узнавать статус авиарейсов и оформлять демонстрационные бронирования. Он определяет намерение пользователя, уточняет недостающие данные, обращается к инструменту статуса или бронирования и отвечает на основе его результата. Контекст разговора позволяет продолжить работу с ранее выбранным рейсом. Используется модель `openai/gpt-6-luna` через OpenAI-compatible API (`https://sprutdock.ru/v1`).

Рейсы и бронирования демонстрационные: данные тестовые, реальный билет не оформляется. Используйте только вымышленные данные пассажиров и паспортов. Не публикуйте API-ключ и не передавайте настоящие паспортные данные; полный номер вымышленного паспорта из профиля показывается в чате по явной просьбе.

## Запуск

Нужны Docker и Docker Compose. Скопируйте пример настроек, укажите ключ в созданном файле `.env` и запустите веб-приложение:

```sh
cp .env.example .env
docker compose up -d --build web
```

Откройте http://localhost:8080. Compose публикует порт только на `127.0.0.1:8080`; сервер проверяет Host и Origin. Приложение однопользовательское, без авторизации: все веб-запросы используют один контекст диалога и обрабатываются последовательно. Контекст диалога хранится в памяти процесса и сбрасывается при перезапуске.

Для терминального чата используйте `docker compose run --rm cli`. Сервис `cli` включён в профиль `cli` и получает TTY: при перенаправлении stdin используйте `docker compose run --rm -T cli`. Вывод в TTY может объединять stdout и stderr; для раздельного перенаправления отключите TTY через `-T`. Веб и CLI используют одну базу, но отдельные контексты диалога.

SQLite хранится в именованном томе `sqlite_data`, путь в обоих сервисах — `/data/flights.sqlite3`. Локальный CLI (`python -m flight_agent`) использует `./data/flights.sqlite3`; путь можно переопределить переменной `FLIGHT_DB_PATH`. При запуске веб-сервера вне Compose (`python -m flight_agent.web`) путь по умолчанию — `/data/flight.sqlite3`; задайте `FLIGHT_DB_PATH`, если нужен другой путь. В обоих случаях требуется переменная `LLM_API_KEY` и установленные зависимости из `requirements.txt`.

HTTP API: `POST /api/chat` с JSON `{"message":"текст"}` возвращает `{"reply":"ответ"}`. Пустое сообщение даёт 400, неверный формат — 422, запрещённый Host или Origin — 403, занятый сервер — 503, непредвиденная ошибка — 500; тело ошибки также содержит безопасное поле `reply`. Страница и её ресурсы отдаются сервером из `flight_agent/static`. Браузер прекращает ожидание через 180 секунд; запрос на сервере при этом может продолжаться, поэтому перед повторным бронированием проверьте результат.

После каждого вопроса чат показывает понятный ответ без технических журналов и JSON. В результатах поиска указываются количество найденных рейсов, маршрут, время, статус и свободные места; если список сокращён, сообщается число показанных рейсов. Альтернативы бронирования перечисляются аналогично. При ошибке выводится понятное сообщение и, когда возможно, совет, что сделать; текст исключения не выводится.

Чтобы посмотреть диагностику веб-чата, запустите `docker compose logs -f web`. Записи `chat started` и `chat completed` связаны по `request_id`. Итоговая запись содержит HTTP-статус ответа (`response_http_status`), статус результата агента (`result_status`), длительность (`elapsed_ms`) и имена и статусы вызванных инструментов (`tools`). При сбое `diagnostics` содержит источник, категорию, код и HTTP-статус внешнего сервиса, если они доступны. В журнал попадают только эти служебные значения.

Примеры запросов: «Какой статус рейса SU123 на 2027-06-10?» и «Забронируй SU124 на 2027-06-12». Для бронирования агент уточнит имя и десятизначный номер вымышленного паспорта. Во время запроса в терминале показывается анимированный индикатор с одной случайной фразой; при перенаправленном выводе он не печатается. Выход: `/exit`, `/quit`, Ctrl-D или Ctrl-C.

Поиск `search_flights` позволяет спросить, например, «Какие есть рейсы сейчас?», «Какие бронирования мне доступны?» или «Сколько перелётов в Москву?». Он работает только с фиксированным учебным расписанием, а не с live-рейсами: без даты ищет по всем датам. Можно указать город вылета (`origin`), прибытия (`destination`), дату `YYYY-MM-DD` и `available_only=true` (есть места и рейс не отменён). Поддерживаются основные формы названий городов из демонабора. `count` — общее число найденных рейсов, `flights` — первые до 10 в порядке вылета, `truncated` сообщает о сокращении; `limit` ограничивается диапазоном 1–10. Наличие меняется при демобронировании и сохраняется в SQLite.

Агенту предписано отвечать без Markdown; CLI дополнительно убирает распространённую разметку из текстовых ответов. Пустой или некорректный ответ сопровождается сообщением об ошибке.

После вызова инструмента результат формируется из его ответа, а не из пересказа модели. Успешную демобронь подтверждает только `book_flight` со статусом `booked` или `duplicate`. Статус `ok` ответа без инструмента означает лишь обычный ответ, а не подтверждение брони или данных рейса; свободный текст модели может содержать ошибки. Модель не может самостоятельно подставить паспорт. Маскирование текста эвристическое и не гарантирует обнаружение всех возможных способов записи личных данных.

Валидный вымышленный паспорт сохраняется в локальном профиле при успешной собственной брони или подтверждении того же паспорта для уже существующей брони, если имя совпадает с сохранённым профилем. Для соответствующей собственной брони сервер может использовать данные текущего хода или паспорт профиля. Ваша реплика в истории текущей страницы показывается как введена. Запрос «Покажи номер моего паспорта» выводит все 10 цифр из локального профиля. Полный номер подставляется при отображении ответа, а в контексте модели и диагностике паспортные данные маскируются. При сбое после вызова инструмента уже полученные результаты и подтверждённая бронь показываются вместе с сообщением об ошибке.

Если вызов бронирования прервался после записи, приложение пытается найти бронь по рейсу, дате и паспорту и показать её номер без повторной записи. Бронирования и количество мест сохраняются в SQLite транзакционно. Для каждого пассажира новой брони хранится допускающий NULL номер вымышленного паспорта; номера в базе демо не шифруются. HMAC-отпечатки для проверки дублей сохраняются, в том числе старые; номер паспорта старой брони появляется при повторе с тем же паспортом.

В Linux TTY приложение включает режим UTF-8 для Backspace и восстанавливает настройки при выходе. Если режим недоступен, используется редактирование строки через readline при его наличии; приглашение ввода выполнено латиницей.

## Проверка

Тесты запускаются отдельным сервисом без передачи ключа. Команда использует `pytest -v -s`, чтобы показать подробности и метрики:

```sh
docker compose run --rm tests
```

Тестовому сервису ключ не передаётся; веб-тесты используют подменённую модель. Для ручной проверки после запуска откройте страницу и отправьте сообщение или выполните:

```sh
curl -s http://localhost:8080/api/chat -H 'Content-Type: application/json' -d '{"message":"Какие есть рейсы?"}'
```

## Остановка и очистка

Завершите интерактивный сеанс через Ctrl+C или выход из чата. Контейнер, запущенный с `--rm`, удаляется автоматически. Остановка веб-сервиса с сохранением базы:

```sh
docker compose down
```

Для очистки ресурсов и локально собранного образа используйте `docker compose down --rmi local --remove-orphans`. Команда `docker compose down -v` дополнительно удаляет именованный том **вместе со всеми сохранёнными рейсами, бронированиями и профилем**.
